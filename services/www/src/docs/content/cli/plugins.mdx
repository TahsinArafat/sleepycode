---
title: "Plugins"
---

Plugins configured in `sleepycode.json(c)` that expose a TUI component are loaded automatically by the CLI. To learn how
to build plugins, see [Building plugins](/build/plugins). You do not need to add the same package to `cli.json`. The CLI
gets the active plugin list from the connected SleepyCode server, so this also works when the server is remote.

Use `cli.json` for CLI-only plugins. These plugins run locally in the terminal and remain active when the CLI connects
to a remote server:

```json title="cli.json"
{
  "plugins": [
    "sleepycode.example",
    "sleepycode.example@1.0.0",
    "@example/sleepycode-tui",
    "@example/sleepycode-tui@1.0.0",
    "./plugins/status",
    "../plugins/status",
    "/home/user/plugins/status",
    "file:///home/user/plugins/status"
  ]
}
```

Entries are processed in order. Prefix an ID or wildcard with `-` to disable matching plugins:

```json title="cli.json"
{
  "plugins": ["*", "-sleepycode.notifications", "-team.*"]
}
```

Pass plugin options with the object form:

```json title="cli.json"
{
  "plugins": [
    {
      "package": "@example/sleepycode-tui",
      "options": {
        "compact": true
      }
    }
  ]
}
```

SleepyCode also discovers plugins under the global config directory and project `.sleepycode` directories. Each plugin uses
the same layout as a published package, with server and TUI entrypoints kept together.

```text title="Plugin discovery paths"
<global-config>/plugins/status/index.ts
<global-config>/plugins/status/tui.ts
<project>/.sleepycode/plugins/status/index.ts
<project>/.sleepycode/plugins/status/tui.ts
```

Discovered plugins can import `@sleepy-ai/plugin/tui` directly; SleepyCode resolves the package at runtime. See
[Building CLI plugins](/build/plugins/cli) for examples.
